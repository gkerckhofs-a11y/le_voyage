# V5 R9D5 — Identité Google raccordée aux espaces provisionnés du staging

29 octobre 2026. Parent `732d0f78dcda10a85b474b5075e67f6148651a1d`, branche `work/v2-phase1-engine`, PR #1.

## Résultat

Le gate Google existant peut fonctionner avec `RC_AUTHENTICATION_MODE=provisioned` et `RC_TEST_ACCESS_MODE=google`. L’adresse vérifiée doit rester dans `RC_TESTER_EMAILS`, et le compte Firebase doit disposer d’au moins un espace autorisé. La liste des testeurs ne crée aucun rôle. Le service applicatif n’initialise aucun profil fictif dans ce mode.

Après vérification Google récente, le gate demande à l’application une session chiffrée pour le même jeton d’identité. Le résultat ouvre `/espaces.html` au lieu du choix d’un profil fictif. Le gate conserve le jeton applicatif opaque côté serveur ; seul le cookie extérieur HttpOnly/Secure est transmis au navigateur. La rotation des espaces reste assurée par le stockage R9B. Le gate vérifie à chaque appel la session Google, son UID et l’adresse encore autorisée.

Les routes de connexion par profil, mot de passe ou échange direct d’identité sont refusées derrière ce gate provisionné pour empêcher de remplacer le compte Google par un autre compte applicatif. La page `/connexion.html` renvoie au sélecteur. La durée extérieure est bornée à l’expiration de l’accès applicatif, au maximum 55 minutes ; le mode démo conserve ses huit heures historiques. La déconnexion explicite du gate révoque aussi la session applicative. Le SDK navigateur se déconnecte après l’échange, y compris en cas d’échec réseau, et n’accepte que les destinations internes prévues.

Le mode Google provisionné n’exige plus les secrets des mots de passe fictifs ou du gate Basic. La clé de chiffrement de session de staging reste requise. Le mode Basic provisionné reste disponible séparément. Aucun fournisseur, domaine, API, liste de testeurs ou secret distant n’est modifié par cette tranche.

## Fichiers

`src/server/firebase-http.mjs` : raccords internes d’ouverture/fermeture de session ; `src/server/google-test-gate.mjs` : mode provisionné et contrôle d’identité ; `src/server/staging-config.mjs`, `scripts/serve-staging.mjs` : configuration explicite ; `src/server/test-access/access.js` : destination/fin de session SDK ; tests gate/configuration et parcours intégré.

**13/13 tests locaux** gate/configuration, avec identité Google simulée : liste autorisée, vérification/récence, Origin/CSRF, session interne non utilisée comme cookie extérieur, rôle non autorisé, destination, refus de changement d’identité, déconnexion et expiration. Tests du mode démo conservés.

**6/6 tests émulateurs** : session interne reliée au répertoire réel du compte fictif, fermeture effective, parcours pilote, connexion provisionnée et sessions partagées. Ce test de raccord interne utilise un jeton mot de passe émulé ; il ne prétend pas effectuer un OAuth Google. Les vérifications du fournisseur Google sont testées dans le gate avec identité simulée.

Soit dix-neuf tests distincts, typecheck, syntaxe et diff réussis. Aucun build web supplémentaire nécessaire : la page d’accès existante est servie par le gate, sans nouveau fichier public. Aucun nouveau test navigateur ou capture locale ; OAuth Google réel reste à recetter.

## Limites importantes pour le pilote

Le gate extérieur conserve encore son registre en mémoire : après remplacement du processus, une nouvelle connexion Google est nécessaire, même si le stockage applicatif est persistant. Ce résultat ne promet pas la continuité de connexion Google entre instances. Le mode reste réservé au serveur de test et aux comptes déjà affectés à un espace. Les nouveaux destinataires sans espace ne peuvent pas utiliser ce gate pour leur inscription initiale ; le parcours d’invitation par mot de passe R9D2 reste distinct. Les comptes Google doivent correspondre aux UID effectivement habilités, sans fusion automatique de comptes sur simple égalité d’adresse.

Avant recette distante : vérifier fournisseur Google, domaines autorisés, liste des testeurs, UID habilités et clé de session stable. Le code ne prouve pas ces configurations. Aucune connexion Google personnelle, habilitation distante, dépense, migration, déploiement ou fusion main effectuée. À la reprise : trois CI du parent vertes, intégration en cours.
