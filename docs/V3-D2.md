# V3-D2 — adaptateur Firebase isolé

27 octobre 2026. HEAD de départ vérifié `b00a8118ba226b46a35e5b677eb27659443d3c3c`, CI accès/moteur/cartes réussies. Branche `work/v2-phase1-engine`, PR 1. CDC V3 §§9–10.

## Réalisation

`src/server/firebase-emulator.mjs` raccorde Firebase Admin Auth à la frontière V3-D1 et Firestore au journal V3-C. L'adaptateur refuse tout environnement sauf `demo-rc-voyage`, Auth sur `127.0.0.1:9099` et Firestore sur `127.0.0.1:8080`. Cet identifiant est un projet fictif d'émulateur, pas un projet Cloud créé. Aucun repli vers la production. Configuration locale dans `firebase/emulators.json`, aucun Hosting ni Functions.

Chaque opération vérifie le jeton avec contrôle de révocation, puis l'affectation active. La transaction relit l'affectation avant de lire et modifier la campagne : un retrait concurrent entraîne le contrôle à nouveau lors d'une reprise transactionnelle. Les résultats sont projetés par l'application existante ; les cadeaux futurs restent privés. La clôture synthétique sert exclusivement à la recette, sans endpoint de production.

Le document privé de campagne contient un instantané JSON du moteur et de son journal, écrit atomiquement, borné à 800 000 octets. Ce format transitoire conserve les clés exactes du moteur ; il devra être découpé ou archivé pour les campagnes dépassant cette limite. Les appartenances sont des documents privés distincts. Les règles `firebase/firestore.rules` refusent toute lecture/écriture directe client ; les accès Admin les contournent et sont contrôlés par l'adaptateur serveur.

## Recette ciblée

`npm run test:firebase` démarre Auth et Firestore et exécute `tests/firebase/emulator.test.mjs`. Cas : configuration de production refusée ; deux utilisateurs créés dans Auth émulateur ; lecture autorisée et refus inter-tenant/équipe ; jeton invalide ; quatre requêtes concurrentes d'une même révision ; franchissement et présentation unique ; reprise via un nouvel adaptateur ; lectures directes anonymes/authentifiées et écriture directe refusées ; retrait d'affectation et compte désactivé refusés.

Dépendances de développement verrouillées : firebase-admin 14.5.0 et firebase-tools 15.34.1, installation sans scripts. La tentative locale a échoué avant les tests : Java 17 disponible, Java 21 requis par la CLI. Le workflow dédié utilise Temurin 21. Les résultats CI sont consignés dans la PR ; ne pas interpréter la tentative locale comme une réussite.

## Limites et suite

Ce raccordement est un adaptateur serveur testé séparément, pas encore une page de connexion ni un remplacement du serveur de démonstration à cookie. Aucune preuve de disponibilité, de sauvegarde, de débit ou de sécurité en production. Les jetons d'émulateur ne constituent pas une validation des signatures de production. Le redémarrage testé concerne le client Admin, pas un arrêt complet et une restauration des émulateurs.

Suite : brancher les routes applicatives sur cet adaptateur, ajouter le parcours de connexion/invitation en environnement isolé, puis les trois réponses hebdomadaires et les préférences privées. Aucune publication, migration ou mutation du projet Firebase réel, aucun changement du moteur ni des cartes.

Sources techniques Google Firebase consultées le 27 octobre 2026 : [Auth Emulator](https://firebase.google.com/docs/emulator-suite/connect_auth), [Firestore Emulator](https://firebase.google.com/docs/emulator-suite/connect_firestore). Elles documentent les hôtes d'émulateur, les projets fictifs et les limites de leur validation.
